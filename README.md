# Crack Attack! — browser port

A browser-native port of the GPL puzzle game
[Crack Attack!](https://www.nongnu.org/crack-attack/), focused on faithfully
recreating the original single-player game in a modern browser.

## What works

- six-column, twelve-row play field with the original rising-stack timing curve
- keyboard, pointer, and touch controls
- horizontal and vertical clears, cross clears, gravity, and chained clears
- original solo scoring, simultaneous-line magnitudes, and causal combo rules
- gray blocks and normal/gray garbage generated by the player's own attacks
- original-style 3D blocks, lighting, garbage unwrapping, stars, signs, and UI
- seven-second danger window, pause, restart, local high score, and lightweight
  generated sound effects

## Architecture

`app/game/engine.ts` is a deterministic simulation with no rendering or React
dependency. Outgoing garbage is emitted through an `AttackSink`. Solo mode
loops that output back through `receiveAttack`; a multiplayer transport can
send and receive the same payloads later.

`app/game/renderer.ts` draws the board through a WebGL-backed 3D layer with a
Canvas fallback, while
`app/game/CrackAttackGame.tsx` handles browser input, audio, animation timing,
and accessible controls.

## Run locally

Requires Node.js 22 or later.

```sh
npm ci
npm run dev
```

Run the simulation and rendering regression tests with `npm run test`.

## Two-player online

Two friends play from one link. A Cloudflare Worker in `relay/` pairs two
WebSockets per room and mints a shared RNG seed; both peers seed identically so
the block sequences match, and each simulates only its own board, exchanging
queued garbage and a tick counter every 32 ticks.

The client needs the relay's address at BUILD time, in `VITE_RELAY_BASE`:

```sh
echo 'VITE_RELAY_BASE=wss://<worker>.<account>.workers.dev' > .env.production
npm run build
grep -o 'wss://[^"]*' dist-pages/assets/*.js   # confirm it was baked in
```

It is a public URL, not a secret — it ships in the client bundle. Without it
the build falls back to `wss://relay-not-configured.invalid`, which can never
resolve, and the game says "Can't reach the game server" rather than retrying
invisibly. Solo play works with no relay at all.

The challenge link is live only: it works while the host keeps their tab open,
and a closed tab cannot be resumed, because peers exchange garbage and a tick
counter but never board state.

## GitHub Pages

The repository includes a separate, fully static Vite build for GitHub Pages.
It uses relative URLs so forks and project sites work beneath any repository
path. The workflow in `.github/workflows/pages.yml` runs the tests on every
push and pull request. The repository's Pages source is configured as `Deploy
from a branch`, using `/ (root)` on `gh-pages`.

**The production deploy is gated on the `VITE_RELAY_BASE` repository variable
being set.** Until it is, pushes to `main` are validated but not published:
the game's live home is https://crackattack.217industries.com, and a second
URL whose multiplayer silently cannot work is worse than none. Set that variable to whichever relay
that site should talk to, and pushes to `main` publish again.

Pull requests opened from branches in this repository get an automatic preview
at `https://whinchman.github.io/crack-attack-online/pr-preview/pr-N/`, where `N`
is the pull request number. The workflow posts the link in a sticky pull request
comment, updates the preview after every push, and removes it when the pull
request closes. Fork pull requests are validated but are not deployed because
their workflow tokens are intentionally read-only.

To verify the Pages artifact locally:

```sh
npm run build
npm run validate
```

For a browser-hosted development preview, open the repository or a pull request
in StackBlitz. The checked-in `.stackblitzrc` automatically starts the static
Pages entry point with `npm run dev`.

## Controls

- Arrow keys or WASD: move cursor
- Space or K: swap
- Enter or L: raise the stack while held
- P: pause
- Touch/pointer: swipe a block left or right to swap it directly
- Touch/pointer fallback: tap a pair to select it; tap it again to swap
- On-screen move pad: touch anywhere and glide in a direction for repeated cursor steps; its broad
  directional zones can also be tapped
